# Dynamic-case evidence

Status: recorded 2026-09-21; no Rust runtime changes.

- `reasoned.json`: initial expectations, written before their cases ran.
- `assertions.json`: explicit JSON-pointer assertions derived from those
  expectations and the rule text; no expected values generated from traces.
- `observed.json`: observations and three replay fingerprints per case and
  implementation, plus environment and native-artifact identities.
- `decisions.json`: subsequent user rulings; separate from measured behavior.
- `assessment.json`: assertion-by-assertion comparison, regenerated by
  `python check.py`. A user ruling is not an implementation pass.
- `recipes/`: fourteen bounded parity recipes.
- `adapter.patch`: the fixed public-API catalogue extension used for the runs.
  It adds observers, not a Python model of runtime semantics.
- `native_probe.cpp`, `CMakeLists.txt`, `native_observed.txt`: supplementary
  native endpoint checks. They do not replace the graph-level traces.

## Replay

Use an isolated hgraph checkout at `15e7bf41b` (the harness base), apply
`adapter.patch`, then run its existing fresh-process runner:

```sh
git apply /path/to/validation/adapter.patch
python -m tools.parity validate
python -m tools.parity replay /path/to/validation/recipes/mapped_ref.json \
  --reference-python /path/to/python-hgraph/bin/python \
  --candidate-python /path/to/cpp-hgraph/bin/python
```

Repeat each recipe three times. The recorded Python runtime is hgraph 0.5.41;
the C++ run used an installed Python-enabled SDK and the authoring package
from source HEAD `628c417f4e46c823668121c05c4a7d0c4f7391f6`. Source HEAD is
context; the installed binaries' hashes identify what executed. New builds
need new evidence. The stale cached wheel used during adapter discovery is
excluded from the final results.

The reference process is Python-first; the candidate executes the C++ runtime
with Python observer nodes. Dictionary APIs may expose bridge differences.
`native_probe.cpp` isolates membership, key-set tracking and binding below
that bridge, using real endpoints at supplied evaluation times.

```sh
cmake -S /path/to/validation -B /tmp/native-contract-build \
  -Dhgraph_DIR=/path/to/sdk/lib/cmake/hgraph \
  -DPython_EXECUTABLE=/path/to/cpp-hgraph/bin/python
cmake --build /tmp/native-contract-build --parallel 2
/tmp/native-contract-build/runtime_contract_probe
```

The installed SDK used here enables Python; the executable links its Python
embedding dependency but its observations use native C++ endpoint APIs.
Native numeric rows are `t valid all_valid modified added-count removed-count
key-set-modified`. `rebind` reports `valid modified added-count removed-count
removed-item-count sampled`; `withdraw` reports `valid modified removed-count
removed-item-count`. Its explicit unbind is separate from the graph-level REF
withdrawal, so their flags are not treated as equivalent observations.

The adapter guards invalid value reads and idle delta reads as the documented
logical observation boundary. It preserves empty modified deltas, withdrawal
deltas and all timestamps. Maps are decoded from the parity runner's canonical
JSON without changing values. Traces retain no physical addresses.

A shared adapter mistake was found before acceptance: `no_key` still
multiplexes the price dictionary. Both runtimes rejected that graph. Rechecking
the intended boundary selected `pass_through`; the input/output expectations
did not change. Runtime errors in the expiry case remain recorded errors.
